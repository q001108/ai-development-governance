# 测试规范

版本：v3.0.1；状态：`COMMUNITY-BASELINE`。接入项目须在自身 `AGENTS.md` 中明确启用范围与生效规则，历史需求保持原绑定。

## 1. 适用与事实源

本文定义测试选择、基线可归因性、环境准备和证据质量。通用验证分级与无副作用约束引用[项目开发总则](./项目开发总则.md)的 `GEN-009`～`GEN-012`；领域行为由接入项目自己的领域规范定义，不在本仓库重复维护。

本文是规划输入，不是自动展开的验收清单。只将当前变更涉及的风险映射到 AcceptancePlan；BA 仍仅来自用户需求或正式业务契约。Profile 不直接决定必须运行多少测试。正文示例不是已执行证据，也不是项目已具备 CI 的声明。

## 2. 风险与测试层级

| RuleId | 级别 | 规则 |
|---|---|---|
| `TST-001` | 必须 | 从当前改动、调用影响和业务风险选择最低成本且可信的验证层级。能由纯函数或切片证明的行为不默认启动完整应用；涉及真实事务、装配、数据库、权限过滤链或协议生命周期时不能用 mock 替代对应集成验证。 |
| `TST-002` | 必须 | 定向测试先行。模块或全量回归必须说明覆盖的共享风险与失败归因依据；不得因 Profile 名称、目录大小或笼统的“更严格”机械扩项。改变共享基础设施时仍可要求广域回归。 |
| `TST-003` | 必须 | 覆盖当前受影响的成功、边界、失败和恢复行为，断言可观察结果与副作用。修复缺陷时优先保存修复前失败、修复后通过的回归证据；客观上只能人工验证时如实说明。不得以调用代码或复制实现替代有效断言。 |
| `TST-004` | 必须 | 控制时间、随机种子、网络、环境变量与共享状态；异步等待有界，测试结束释放自己创建的资源。测试只能使用隔离数据和可清理资源，不连接生产端点、不清空共享数据库、不泄露敏感信息。 |

| 变更影响 | 选择验证的依据 |
|---|---|
| 局部配置、普通展示或纯逻辑 | 直接相关断言；仅在启动行为、布局或真实交互是目标时增加运行验证 |
| API 与序列化 | 当前契约的 HTTP 状态、错误语义、输入和 ID 表达；未修改的认证机制不自动展开全角色矩阵 |
| 权限与工作区 | 受影响的允许、拒绝和跨工作区负例；不得因定向测试而省略安全边界 |
| 导入导出、文件和数据库事务 | 当前格式契约、路径与 ZIP 安全、凭据排除、授权及原子性；不得只测成功路径 |
| 状态、异步与事件流 | 当前状态迁移、重复/乱序、取消与恢复、过期请求和资源释放 |
| 迁移和方言 | 受影响方言及升级路径；内存数据库不能证明生产数据库方言兼容 |
| 桌面端、聊天端或插件 | 当前受影响的 IPC/生命周期、宿主隔离、会话或插件边界；安装包与全平台冒烟仅由对应发布影响触发 |

安全、迁移、事务及共享契约的实际风险不能因环境成本高而降为建议。浏览器测试用于真实用户路径和布局；DOM 单测不证明真实视觉效果。所有矩阵均按当前影响选择，不对无关模块追加工作。

## 3. 测试基线与候选失败归因

| RuleId | 级别 | 规则 |
|---|---|---|
| `TST-005` | 必须 | 用作候选阻断依据的广域测试必须有同环境可重复基线，或有能唯一归因于候选改动的直接证据。未经归因的失败不直接计为候选 FAIL；也不能因其疑似既有而记为 PASS。 |
| `TST-006` | 必须 | 基线记录固定代码 revision、测试集合及命令、依赖/工具链与配置指纹、操作系统和必要服务/数据前提、执行时间、结果和脱敏证据。由运行时组织准备，实际执行者提供事实，QA 核查与当前验证的可比性；新提交本身不自动使旧基线有效。 |
| `TST-007` | 必须 | 测试源码、命令/选择器、依赖锁定、工具链、运行配置、平台、必要服务或数据条件变化时重新评估基线；影响可比性的变化使基线失效。有效性取决于这些条件，不按固定天数推断。无法确认时保持未知/阻塞，不伪造干净基线。 |
| `TST-008` | 必须 | 候选范围外的既有失败保留失败事实、归因依据、责任方和后续处理引用。隔离或替代原阻断验证必须走受控计划纠正，并由替代集合覆盖同一真实风险；不能通过改名、删除测试、重跑到绿或转 AD 掩盖候选失败。 |

记录复用已有候选/就绪/验证事实的引用，不为每个需求再建完整基线台账。只有确需共享且已经验证的基线才单独保存；引用需固定版本和摘要。仅有“之前也报错”的口头描述不构成已知失败证据。

| 实际情况 | 质量结论与后续 |
|---|---|
| 当前候选导致可重复、可归因失败 | FAIL，进入正常返工；其他环境阻塞继续保留 |
| 缺工具、权限、服务或依赖导致必要验证不能执行 | BLOCKED/准备等待，通知责任方，沿环境恢复路径处理 |
| 基线同环境复现相同失败且有影响分析 | 保留既有失败；受控纠正完成前原阻断项仍阻塞 |
| 基线不可重复或原因未知 | 归因不足，保持阻塞；进一步定位或受控设计等价验证 |
| 所有当前有效阻断项实际通过或合法复用 | 可形成质量 PASS，但不代表原全量套件通过，也不替代人工业务验收 |

## 4. 环境准备、人工介入和同轮恢复

| RuleId | 级别 | 规则 |
|---|---|---|
| `TST-009` | 必须 | 验证前逐项检查工具、权限、命令、服务入口和数据前提。对明确且可逆的瞬时环境故障最多做一次有依据的自主恢复尝试；无法自主解决时报告已尝试操作、阻塞项、人工责任与客观恢复条件，然后等待。不得安装依赖、反复重启或扩大权限来掩盖未就绪。 |
| `TST-010` | 必须 | 同一候选、相同环境阻塞且无新解除证据时，不重复派发、不新建 QA 轮次、不增加质量失败计数，也不通过重开进程或角色重置恢复次数。用户回复“继续”只触发最小就绪检查，不等于环境已恢复。 |
| `TST-011` | 必须 | 人工恢复后先检查阻塞解除和候选摘要；候选及有效验证计划不变时继续原 QARound，追加独立结果事件和恢复引用，不覆盖原 BLOCKED。仅执行未完成或证据已失效项，按复用规则保留有效 PASS；候选变化时重新验证，不能跨候选复用。 |

未启动 QA 时没有 QARound，环境恢复后才创建首轮。已经启动时区分“逻辑 QA 轮次”和“不可变结果事件编号”：同轮可有阻塞与恢复事件，不得复用 EventId。机器绑定和去重规则由[治理运行时事实协议](../Agent治理/治理运行时事实协议.md)定义；本节不建立第二套事件状态机。实际代码缺陷导致启动失败仍属候选失败，不能以“启动不了”一律归为环境问题。

## 5. 命令、证据与平台

| RuleId | 级别 | 规则 |
|---|---|---|
| `TST-012` | 必须 | 验证命令取自当前源码、脚本和冻结计划。修复型 lint、生成源码、修改候选的构建不作为只读 QA 命令；有副作用构建沿现有隔离产物规则执行，不自动清理用户文件。 |
| `TST-013` | 必须 | 报告实际命令、选择范围、平台、退出码、失败/跳过/未执行及必要脱敏证据。覆盖率是风险线索，不设无基线的全局比例门禁；flaky 失败保留首次结果和处理期限，不无限重跑。 |
| `TST-014` | 必须 | 治理版本、业务候选 revision/摘要与测试规范版本分别绑定；规范引用固定文档版本及内容摘要或 Git revision，不使用“最新版”。Windows/macOS 结果不能表述为 Linux 生产或 CI 通过。 |

具体命令以接入项目的脚本和领域规范为准，本仓库不复制第二份命令清单。带自动修复或代码生成副作用的命令不能直接作为只读 QA 命令；是否执行全量构建应由实际影响与候选风险决定。

本阶段无 Linux CI，不新增 PR/夜间/发布流水线义务，不把尚未具备的 WebChat 测试框架、覆盖率基础设施或全平台安装冒烟作为所有需求的前置条件。真实安全、迁移或发布风险仍需相应验证；无环境时如实保留限制。

## 6. 接入要求

接入项目应在自己的 `AGENTS.md` 中声明本规范的适用范围、实际测试命令、可用平台与交付环境。CI、夜间任务、发布流水线和全平台冒烟只有在项目真实具备并被当前风险触发时才构成门禁；不得把社区模板中的示例当作已存在能力。
