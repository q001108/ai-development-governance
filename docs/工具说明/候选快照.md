# 候选原始字节快照（B2 开发候选）

此工具将已完成 Writer 交接中的明确交付路径固定为可核验的快照，支持暂存、未暂存、删除、Git 索引可观察的重命名，以及显式声明交付的未跟踪文件。快照与待登记候选事实草稿分开；正式 CandidateRef、候选事件保存、派发及结果绑定仍由现有运行时负责。

这是未发布的可选工具格式 `SnapshotFormatVersion=v1.0`，不更改现有治理 Schema 或旧候选摘要算法，不实现 B4 中间计划前驱，也不要求为采集快照提交代码。

## 运行位置与接口

运行时在收到已完成 Writer 交接、明确当前需求/上下文/谱系和精确交付范围后调用：

```python
capture_snapshot(
    repo,
    requirement_id="REQ-DEV-20261028-01",
    context_version="v1.0",
    repair_lineage_ref=None,
    baseline_revision="<已存在的完整 Git commit SHA>",
    writer_handoff_refs=["docs/requirements/REQ-DEV-20261028-01/facts/writers/WR-001.json"],
    scope_paths=["src/module.py", "tests/test_module.py"],
    untracked_paths=["tests/test_module.py"],
    expected_files={"src/module.py": "<原始字节SHA256>", "tests/test_module.py": "<原始字节SHA256>"},
)
```

示例路径、编号及 SHA 只是占位，不能当作项目已存在的事实。scope_paths 为已授权交付的精确路径，不是递归目录或 glob；必须与所引用 Writer Changes 的路径集合相符，索引重命名还包含旧路径。不允许漏掉交接内容，也不自动把仓库其余修改带入本次候选。

expected_files 是调用方在接收交接时固定的字节预期，删除路径使用 null；给出时必须完整覆盖 scope_paths 并与实际字节一致。此输入可以由运行时采集，不要求开发者重填清单。未提供时输出 ExpectedFileDigestsChecked=false。即使提供，也只证明内容与调用方预期一致，不证明修改作者身份：AuthorshipVerified 始终 false，ChangeAttribution 固定为 CALLER_SCOPED_NOT_AUTHORSHIP_PROVEN。同一个文件中不同人的混改不能靠文件名或 Git 状态自动分离，必须由运行时确认交接范围，不能宣称工具已经证明作者归属。

命令行对应：

```powershell
python scripts/governance_candidates.py capture --repo . --requirement-id REQ-DEV-20261028-01 --context-version v1.0 --baseline <完整SHA> --writer-handoff docs/requirements/REQ-DEV-20261028-01/facts/writers/WR-001.json --path src/module.py --path tests/test_module.py --untracked tests/test_module.py
```

--writer-handoff、--path、--untracked 均可重复。命令行不接受 expected_files，因此如需交接时的字节预期约束，应使用 Python 接口；不会把未核验预期当作已核验。

## 采集与覆盖边界

Git 查询均使用字节输出，中文路径通过 NUL 终止记录解析，文件内容直接 read_bytes，不经 PowerShell 文本管道。基线从固定提交及 Git blob 读取，当前内容从工作树读取，索引对象 ID 单独保存，所以暂存后又产生未暂存修改时不会误用暂存区内容作为最终交付。

基线与当前内容都按原始字节 SHA-256 保存；CRLF 与 LF 是不同字节，不进行换行、编码或文本规范化。Git 自动转换过换行的工作树可能与 Git blob 不同，工具按实际交付字节解释，不能仅凭 Git 的“clean”推断两者字节相同。二进制资产与文本使用同一摘要算法。

敏感信息筛查额外使用 UTF-16/UTF-32 的 BOM 及常见 NUL 编码扫描视图，并直接匹配原始视图中的凭据赋值语法，避免 JSON 原文二次转义隐藏引号。扫描视图不用于保存或摘要，安全的 UTF-16/UTF-32 文件仍按原始字节交付；这些启发式检查不构成完备的密钥识别保证。

重命名使用索引中的 Git 元数据，不调用工作树 clean filter、外部 diff 或 textconv；新增与删除的原始内容均保留。如果尚未暂存的改名无法客观确定来源，以原交接中显式 DELETE+ADD 表达，不根据近似文件名猜测源路径。索引冲突、符号链接、junction、submodule 和非普通文件在本候选中拒绝处理。

只读取明确交付文件及其基线 blob；其他开发者在范围外的工作树内容不读取、不复制、不恢复。文件名、路径及选定原始字节经过敏感内容检查；.env、私钥/证书私钥文件、常见凭据文件和运行数据库/日志/缓存/构建目录拒绝交付。此检查不等于完备的凭据识别器，调用方仍须遵守原项目的敏感信息与交付审查规则。单文件上限 32 MiB，快照 blob 合计上限 128 MiB，路径上限 4096 个。

采集前后重新读取交付文件、索引信息、交接原文摘要及 HEAD；不稳定则拒绝发布。它不能锁住其他进程，也不能证明两次观测间绝无瞬时变化；运行时必须使用受控稳定工作区。不会通过自动 commit、stash、reset 或文件还原取得“稳定”。Git 查询移除继承的 GIT_* 重定向和 trace，禁用 optional locks、替换对象及 fsmonitor，不查询远端。

同时自动绑定当前需求中存在的 control-profile.json、acceptance-plan.json、开发上下文包.md，以及可选 rules-projection.json 的原始字节摘要，保存为 GovernanceInputs 并在采集前后复核。前三份齐全才有 GovernanceInputsComplete=true；verify_snapshot 提供 repo 且实际字节核对成功时才有 GovernanceInputsChecked=true。纯字节快照可以保留空/不完整绑定，但不得把它解释为已核验冻结治理输入。同版本的上下文、计划或规则投影被原地改写，以及后来新增规则投影时，当前仓库核验都会拒绝旧绑定。

Writer 交接所在需求存在 FACT_CORRECTION 或非空 SupersedesEventRef 时，本候选不猜测纠正后的有效来源，交回现有运行时处理。普通 QA/就绪事实的新增不影响候选交付字节核验。

## 存储、草稿与核验

默认存储：`docs/requirements/<RequirementId>/snapshots/<SnapshotDigest>/`。其中 snapshot.json 为规范化 UTF-8 JSON，blobs/<SHA256> 为原始字节；目录名等于 manifest 的 SHA-256。文件内容相同并且需求、上下文、工作树和交接绑定相同，会得到同一个摘要；摘要不包含采集时间，避免同内容反复生成不同对象。

先写入同一目标根下本次独占的 pending 目录，再发布内容寻址目录。已有同摘要快照只验证，不覆盖；内容被改写或存在未绑定文件时拒绝继续。失败时只清理精确创建且经过绝对路径校验的 pending 目录，不删除已有快照或用户文件。拥有全仓库改写权限者仍可能同时改写所有来源；核验依赖运行时保留的预期摘要，不把“旁边有个哈希”当作独立可信批准。

可以显式选择仓外或 Git 私有目录作为 output_root；此时草稿标 LocalOnly=true、CannotArchiveAsFact=true，不可把本机私有快照当作已完成长期归档的正式候选。

返回 CandidateFactDraft 仅供现有运行时审查后登记。CandidateRef=null，Payload 包含：

- SnapshotFormatVersion、CandidateSnapshotRef、CandidateSnapshotDigest；
- BaseCommitSHA、CandidateCommitSHA=null、WorkspaceRoot；
- ChangedPaths、UntrackedDeliveryPaths、WriterHandoffRefs；
- LocalOnly、CannotArchiveAsFact、DraftOnly=true、QualityPassed=false。

默认 CandidateSnapshotRef 使用仓内 POSIX 相对路径并指向 snapshot.json；调用 verify_snapshot 时可传入其绝对路径，或以目标仓根拼接相对路径。外部快照引用是本机绝对路径，不得随社区模板传播。

```python
verify_snapshot(
    snapshot_dir_or_manifest,
    repo=repo,
    requirement_id="REQ-DEV-20261028-01",
    context_version="v1.0",
    repair_lineage_ref=None,
    expected_snapshot_digest="<原事实已绑定的摘要>",
    verify_worktree=True,
)
```

静态核验始终检查格式版本、目录/manifest 摘要、完整路径集合、blob 字节及大小、无多余内容。提供 repo 时还核对工作树归属、基线 Git 对象和交接原文摘要；verify_worktree=True 另核对当前交付文件是否仍与快照一致。它只看交付文件，后来新增的 QA/就绪事实不会被误当作候选代码变动。

manifest 内的 Files、ScopePaths 和 Renames 相互闭合；提供 repo 时还要求 ScopePaths 精确覆盖已绑定 Writer Changes，加上已声明改名的旧路径。因此即使有人删掉一项交付并另算一个新 manifest 摘要，也不能通过真实 Writer 来源核验；原事实固定的 expected_snapshot_digest 还能直接拒绝任何不同摘要。基线 blob 在静态核验中按 Git blob 头计算原对象 SHA-1/SHA-256，提供 repo 时再核对原 tree；索引信息是采集时的独立对象引用，最终交付始终以 Current 原始字节为准。

```powershell
python scripts/governance_candidates.py verify --snapshot <snapshot.json绝对路径> --repo . --requirement-id REQ-DEV-20261028-01 --context-version v1.0 --digest <原事实摘要> --verify-worktree
```

核验成功不生成正式事实，不授权 G2、QA、人工验收或发布，也不让相同字节的新 CandidateRef 继承旧质量结果。核验旧格式候选应继续使用其原格式；未知格式不能用本工具猜测为通过。

CLI 成功退出 0；无法采集/核验或输入不合法退出 2，并输出通用脱敏错误，不回显未受信文件正文、路径错误细节或凭据值。

## 验证范围

专用测试使用临时 Git 仓库，覆盖 CRLF/LF、中文路径、二进制、暂存/未暂存、删除/索引重命名、未跟踪声明、范围遗漏、跨需求/上下文绑定、敏感文件、采集中变化、Git 环境污染、篡改及快照幂等。实际平台和测试数量以本轮验证报告为准，不将本机结果外推为真实公司项目或跨平台已验证。

本轮本机 Windows / Python 3.12 验证：18 项专用测试通过（26.368 秒）；另在隔离仓库通过真实 CLI 完成 capture 与 verify --verify-worktree。包含同版本治理输入原地变化、规则投影新增后旧候选失效，以及删交付项后重算 manifest 摘要仍被 Writer 来源核验拒绝的负例。全量工具回归由集成阶段统一执行，公司项目与其他平台尚未验证。

随后补充 UTF-8 JSON 原文及 UTF-16/UTF-32 凭据绕过防护：最终 19 项专用测试通过（28.412 秒），覆盖有/无 BOM、LE/BE、NUL 对齐变化和安全 UTF-16 数据原字节保留。核心治理工具未改。
