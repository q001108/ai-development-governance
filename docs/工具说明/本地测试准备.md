# 本地测试前环境准备（B1 开发候选）

本工具围绕本地测试提供“读取测试定义 → 检查 → 自动准备 → 复查 → 执行衔接 → 清理”。它不新增治理阶段，不修改已发布 v3.0.2 的 Schema、角色职责、候选规则、恢复预算或历史事实。

原 `governance_environment.py` 继续只读。新增 `governance_local_tests.py` 负责实际准备与执行，`governance_test_session.py` 为主智能体和独立 QA 保持同一次环境；首次接入时配置项目已有脚本并启用 Automatic=true，之后由治理入口自动调用，不为每条需求另填环境清单或要求用户输入命令。当前是可审阅的本机候选，尚未接入公司项目或证明跨平台可用。

## 使用位置与输入

主入口是实际测试前。LEAN 可服务 Writer 的计划内验证；STANDARD / CONTROLLED 由现有运行时组织准备，在资源存活期间保存逐项 TEST_READINESS、核验当前候选并派发独立 QA。B1 不生成候选、正式就绪事件、QA_RESULT、轮次或路由，不替运行时判断人工恢复授权。

工具从当前仓库的固定位置读取：

- `docs/requirements/<RequirementId>/control-profile.json` 与 `acceptance-plan.json`，先调用现有 live 计划校验器；
- 同目录 `开发上下文包.md` 中的产物版本、FROZEN 状态、5.2.1 验证定义及 5.2.2 执行控制表；
- `facts/gates/` 中唯一匹配该上下文版本的 G2 FROZEN 事件；
- 项目已有配置中的可调用准备入口。

这只是消费已有来源及检查一致性，不替代运行时的完整门禁、候选摘要和纠错核验。存在 FACT_CORRECTION 或 SupersedesEventRef 时，本候选不猜测有效来源，停止并交回现有运行时处理。当前检查最多读取 1024 份需求事实。

验证定义首轮采用单个 ValidationId 对应单个 ControlId；不支持的多控制合并、歧义表格和缺失覆盖明确报错。测试方法必须与 AcceptancePlan 的 Method 一致，Owner、触发状态和阻断类别同样核对；只执行当前 Owner 已触发的测试，不将其他角色或未触发项列为未执行。不能自动执行的断言、建议方法及非本机平台明确保留原因，不猜测命令。

## 项目接入一次，后续自动读取

项目准备定义只能有一个正式来源，三选一：

| 已有配置位置 | 扩展位置 |
|---|---|
| package.json | `governance.localTests` 对象 |
| pyproject.toml | `[tool.governance.local-tests]` 及其子表 |
| 其他项目 | 仓库根 `governance.local-tests.json` |

多个来源同时出现时报告冲突，不静默挑选。配置本身及单份相关元数据上限 256 KiB，最多 128 个命令、32 个资源。没有配置时，报告 MISSING_PROJECT_ENTRY；不自动创建配置、不修改业务脚本或冻结计划。

由接入 Agent 从项目现有启动、测试、夹具脚本整理以下映射，供项目审阅后长期复用。它只描述调用接口和资源关系，不重复保存需求状态、READY 声明、候选或测试结果。以下为合成格式示例，脚本名不能直接当作项目已具备的入口：

```json
{
  "LocalTestProtocolVersion": "v1.0",
  "Automatic": true,
  "Commands": {
    "python scripts/test_api.py": {
      "Argv": ["{python}", "scripts/test_api.py"],
      "TimeoutSeconds": 60
    }
  },
  "Resources": {
    "API": {
      "Kind": "SERVICE",
      "Requires": [],
      "Start": ["{python}", "scripts/local_api.py"],
      "Check": ["{python}", "scripts/check_local_api.py"],
      "Port": 18080,
      "AllowPortOverride": true,
      "TimeoutSeconds": 20
    },
    "DATA": {
      "Kind": "FIXTURE",
      "Requires": ["API"],
      "Prepare": ["{python}", "scripts/prepare_test_data.py"],
      "Check": ["{python}", "scripts/check_test_data.py"],
      "TimeoutSeconds": 10
    }
  }
}
```

Commands 的键精确对应原 AcceptancePlan.Method；Argv 是同一项目命令的显式参数数组，避免猜测 shell 引号与 Windows 路径。资源支持 SERVICE、FIXTURE 和 CHECK：前两者调用 Start 或 Prepare 后检查；CHECK 只调用 Check，可用于工具版本、现有登录会话或其他本地前提核验。资源依赖必须存在且无环。超时按命令设置为 1～300 秒，不安装、升级依赖或扩权。

可选 PassThrough 是允许传给子进程的环境变量名列表，只写名称，不存放值。默认仅传递 PATH、临时目录、用户目录及必要工具链等基础变量，应用数据库地址、端点和凭据不从父进程自动继承，历史 B1_* / GIT_* / PYTHON* 也不会带入。项目确需的本机值应按实际授权显式选择，不能把生产/共享数据库凭据当作独立测试数据配置。变量内容和完整环境表不会进入诊断。

在既有上下文包的“环境依赖 / Readiness / 派发前检查”单元格中引用这些已有入口，例如：

```text
DATABASE / PLANNED / LOCAL:DATA
BACKEND / READY / LOCAL:API, LOCAL:DATA
NONE / N/A / N/A
```

首轮接受 BACKEND、DATABASE、BROWSER_SESSION、OS、LOCAL、TOOLS、FIXTURE 类型；资源引用只接受明确的 LOCAL:<ID> 列表。自然语言前提、混合未知内容或未适配的入口保留为 UNMAPPED_PREREQUISITE，不因有一个有效引用就忽略其余条件。READY/PLANNED 只沿用规划状态，执行前仍实际运行 Check。

这些是可选工具的引用约定，不是给历史上下文包强行补字段。后续项目接入或规划时按其实际规则准备；冻结后发现来源不够，不能在测试过程中偷偷改计划。

## 测试前自动调用

项目采用本候选时，在其唯一配置来源设置 Automatic=true，并合并根 AGENTS 中的 B1 自动调用入口及 Writer/QA 对应增量。主智能体执行既有测试流程时自动触发，不等待用户额外输入命令。开关默认关闭，旧项目或历史需求不会因复制工具自动采用新行为。

LEAN 由 Writer 自动调用准备与本地验证。STANDARD / CONTROLLED 由主智能体先核对候选和派发条件，再自动启动短期环境会话、消费逐项就绪观察，按原协议保存正式 TEST_READINESS，将 SessionId、已就绪 ValidationId 和原轮次/候选交给独立 QA。QA 的 test 动作在该会话中执行已选定命令；主智能体在 QA 完成、取消或异常后自动 stop 并核对清理，不把操作交给开发者。

会话就绪后的受理窗口默认为 600 秒，运行时可按本轮预算设置 --seconds，范围 1～1800 秒；窗口到期不再接收新测试，当前已开始的命令仍受自己的超时限制，结束后自动释放本次服务与数据并报告会话已结束。会话不常驻、不轮询项目需求、不创建智能体、不分配质量轮次；它只弥补主智能体准备与独立 QA 实际执行之间的资源存活。QA 会话过期时保持实际未验证/阻塞，不能使用旧端口或伪造通过。没有新解除证据时，主智能体不得通过重复 start 重置恢复预算。

下面这些命令由主智能体和 QA 角色调用，也可用于排查；不是开发者每次测试的手工步骤：

```powershell
python scripts/governance_test_session.py start --repo . --requirement-id REQ-DEV-20261028-01
python scripts/governance_test_session.py test --repo . --session-id <start返回的SessionId> --validation-id V-02
python scripts/governance_test_session.py stop --repo . --session-id <同一SessionId>
```

固定发行接入项目中，test/stop 还需携带原需求版本选择，例如 `python .governance/run.py governance_test_session stop --for-requirement <原RequirementId> --repo . --session-id <同一SessionId>`；start 的 --requirement-id 可直接用于选择。QA 与清理沿同一绑定调用，不能因默认插件已升级而改用另一发行。

固定发行新接入项目通过 .governance/project.json 的 LocalRuntimeDirectory=.governance/local 显式选择被 Git 忽略的本地运行目录。会话文件位于其中的 local-tests/sessions/<SessionId>，诊断位于 local-tests/，临时服务与数据位于 runs/ 的独占子目录；本地状态不进入候选或发行。运行目录继承项目文件系统权限，不存放凭据；POSIX 子目录继续使用 0700。Windows 使用项目继承 ACL，避免 Python 3.12.4 起的 tempfile 私有 DACL 令受限令牌无法重新访问自己创建的目录。选择目录未被忽略、含跟踪文件、路径不符或存在符号跳转时拒绝使用。

未声明该适配的历史副本项目继续原 Git 私有目录及系统临时目录方式；其运行环境需要允许相应写入。在 Codex 工作区沙箱中 .git 受保护，不能通过扩大权限掩盖适配缺项；已有项目升级后由项目端显式补充 LocalRuntimeDirectory 和对应忽略项，旧需求不自动迁移。

会话只交换已准备的验证 ID、就绪观察、测试命令观察和停止信号，不复制完整环境变量或凭据。每项命令实际执行前再次核验前提和源码未变，不执行未准备的 ValidationId。主智能体仍负责候选摘要和正式事实，QA 仍负责原始质量结论。

## 手动排查与程序接口

仅预览，不启动服务或测试：

```powershell
python scripts/governance_local_tests.py --repo . --requirement-id REQ-DEV-20261028-01
```

LEAN / Writer 已获准的本地命令验证，可显式执行：

```powershell
python scripts/governance_local_tests.py --repo . --requirement-id REQ-DEV-20261028-01 --run
```

命令中的需求编号是占位示例，必须使用已存在的需求。工具默认按 Profile 选择 WRITER 或 QA，也支持显式指定 Owner。QA 不允许使用 --run 绕过独立派发，必须走下述运行时回调。

运行时接口为 `project(repo, requirement_id, owner)` 生成输入，再调用 `execute(request, dispatch=callback)`。callback 接收三个参数：就绪验证项、本次环境变量，以及包含完整资源检查、全部验证就绪观察和来源摘要的报告副本；调用期间服务和数据保持存活。callback 负责核验当前候选，将这些客观观察按协议保存为正式逐项 TEST_READINESS，等待独立 QA 完成，再返回。没有就绪项时不调用 callback，运行时使用返回的阻塞报告保存正式等待事实。只读 Reviewer 继续原流程。B1 只记录已交付哪些验证项，不复制角色结果或宣称 QA PASS；回调异常仍清理资源并保存最小诊断，再将原异常交给调用方。

环境解除后的重验可由运行时传入 `validation_ids=[...]` 子集；CLI Writer 模式对应重复的 `--validation-id V-02`。子集必须来自同一份已生成输入，只准备该子集的依赖。此选项不自行判断旧 PASS 是否可复用，不分配 QARound，也不能把子集通过写成全量通过；原候选、原计划、解除证据和复用合法性继续由运行时核验。相同阻塞无新解除证据时，运行时不得重复调用准备或派发；本工具无常驻重试循环。

## 本次运行的资源约定

工具向启动、准备、检查和测试两端提供同一组运行变量，不写回业务配置：

| 变量 | 用途 |
|---|---|
| B1_RUN_ID / B1_REQUIREMENT_ID / B1_CONTEXT_PACK_VERSION | 当前运行、需求与上下文标签 |
| B1_REPOSITORY_ROOT | 当前工作树根 |
| B1_RUN_DIR | 本次创建的独立临时根 |
| B1_<资源ID>_DIR | 该资源的独立数据目录 |
| B1_<服务ID>_PORT | 本次分配的 127.0.0.1 TCP 端口 |

Start 必须以前台进程形式持续运行，入口及其子进程全部归本次进程树。数据库和夹具脚本应把测试数据放在上述目录或同等可核验的独立命名空间；脚本必须实际消费这些变量。首轮不管理外部数据库、Docker、已有共享服务或人工登录操作；相应条件可使用项目 CHECK 核验并在不足时报告。

Check 以退出码 0 表示其负责的客观条件已满足，其他退出码或超时表示未就绪。服务 Check 应验证本次 RunId/工作树/数据归属及必要业务前提，不能只检查 TCP 端口可连接。测试夹具的 Check 应检查真实数据条件。声明有这个入口，不等于它已经验证正确；接入项目必须测试其行为。

已占用端口仅在 AllowPortOverride=true 时改用临时端口，启动和测试入口都读取同一个 B1 变量。工具不终止占用者。端口选择与真实绑定之间仍有竞争窗口，服务必须成功启动并通过实际检查才算就绪；不能用“刚才端口空闲”推断启动成功。首轮总是管理自己新建的服务，不自动复用归属未知的已有实例。

工具先检查所选命令与资源所用程序是否可找到；程序从本机绝对 PATH 目录解析，排除 UNC 和当前目录回退。{python} 使用运行工具本身的解释器；项目若使用另一解释器，应提供对应的项目批准入口。显式参数数组不经过 shell 字符串拼接；Windows .cmd 等包装器及项目脚本本身仍属于项目受信执行入口。工具不是任意脚本的安全沙箱，不能将来源不明的命令写进配置后直接执行。

首次启动、夹具准备各做一次；只有服务 Check 可在有界启动时间内轮询，不重启服务、不重复造数据。失败仅阻塞依赖它的验证，就绪子集继续。每个本地测试执行前再次检查其前提；服务失效或源码变化时，受影响测试不执行。

## 清理、诊断与结果边界

正常、测试失败、超时和可捕获中断都释放本次创建的进程树与临时目录，保留原有开发服务和业务数据。Windows 使用无窗口的受控 Job Object，真正的项目进程在归入 Job 后才启动；POSIX 使用独立进程组。只有本次精确创建的临时根会被递归清理，先检查绝对路径和归属；从不自动 reset、恢复或删除项目文件。清理失败明确报告，不伪装完成。进程树无法确认停止时保留本次数据目录，记录 OwnedRunDirectory 和恢复动作，避免在进程仍运行时删数据；后续只处理该精确目录，不自动扫除其他历史目录。强制终止宿主、断电等情形不在当前自测覆盖内。

执行前后核对 Git 跟踪及未忽略的未跟踪文件的原始字节摘要，发现变动则停止后续测试并报告 REPOSITORY_CHANGED；既有修改不恢复。这是写入防护，不是 B2 候选快照，也不能替代正式候选摘要检查。忽略文件、外部资源及脚本自身的全部副作用不由该摘要证明。运行时回调仅允许新增本需求 readiness/qa 的 JSON 事实，既有事实和源码保持原值；B1 不校验这些新增事件的完整语义，仍由运行时负责。

最小 JSON 诊断保存在本工作树私有 Git 目录的 `governance/local-tests/<RunId>.json`，使用独占新文件，不覆盖历史报告，不写共享治理事实或第二套需求状态。保留来源摘要、逐项就绪观察、退出码、耗时、缺项、恢复动作和清理结果。程序 stdout/stderr 原文丢弃，避免凭据进入通用日志；需要业务详细证据时，项目测试入口应按既有规则另产脱敏证据。LocalReportPath 给出本机诊断位置，不作为质量事实引用。

输出固定标明 GatesChanged=false、QualityPassed=false、FormalReadinessWritten=false、CandidateBinding=RUNTIME_VERIFICATION_REQUIRED。PreparationSummary 仅描述本次调用选择的验证子集，Execution/Observation 记录真实命令执行，不映射为候选 FAIL 或 QA PASS。退出码 0 表示本次所选阻断命令成功且无执行/清理问题；1 表示所选阻断项受阻、命令非零/超时或清理异常；2 表示来源、配置或调用输入无法可靠处理。预览无执行，其退出码只反映输入映射是否完整。

## 验证范围

专用测试使用临时 Git 仓库、合成冻结计划、回环 TCP 服务及临时夹具，覆盖动态端口、部分就绪、失败/超时、进程子树回收、数据清理、源码变动、缺项、输入绑定、配置冲突和脱敏诊断。实际平台及测试数量以本次验证结果为准，公司产品项目的数据库、框架、浏览器会话和现有准备脚本仍待后续真实试用。

2026-10-28 本机 Windows / Python 3.12.7 验证：24 项本地测试准备专用场景通过；完整治理工具回归 151/151 通过（130.500 秒）。另以真实 CLI 在隔离样例中执行 2 个所选命令，确认资源清理完成、最小报告落盘、Git 可见项目文件字节保持不变；文档 JSON 示例经实际配置解析器校验。原结构检查及候选说明的表格、链接、语法和差异检查通过。这些结果不外推为公司项目已采用或 Linux/macOS 已验证。

同日补齐测试前自动触发入口：根 AGENTS、Writer/QA 增量及短期会话桥接。最终完整回归 155/155 通过（163.017 秒），包含 4 项会话专用场景。另跨两次独立工具调用验证：准备命令退出后，后续 QA 命令仍能使用原端口与数据；stop 后服务和数据清理完成。会话正常停止、到期清理及未启用时拒绝自动启动均已覆盖。实际主智能体按角色入口触发的公司项目流程仍待后续试用，不能把模拟会话验证写成公司已接入。
