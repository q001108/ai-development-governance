# 只读状态与修复交接查询（B3 开发候选）

本工具从当前可校验来源查询阶段、缺项、阻塞、当前候选及下一动作，不根据聊天或开发记录中的状态文字判断通过。StatusQueryVersion=v1.0 是查询输出格式，不是新治理版本；查询不写文件、保存事实、派发角色、分配轮次、修改计数或推进门禁。

## 输入与调用

```powershell
python scripts/governance_status.py --repo . --requirement-id REQ-DEV-20261028-01
```

编号只是占位示例，必须使用已有需求。Python 接口为 query_status(repo, requirement_id)。工具固定读取该需求的 control-profile.json、acceptance-plan.json、开发上下文包.md 和 facts，沿用现有 live 计划校验、来源/G1 绑定、事件 envelope 校验及已有质量投影校验器。

首轮支持已形成可校验计划的需求。规划输入缺失时明确 UNDETERMINED，不从未保存的聊天反推 G1，也不为完成演示补造决定。上下文包中的工作包、验证控制映射与计划不一致、同一当前版本存在多份 G2、事实目录或引用错误时同样停止推断。

## 当前支持的状态

| 已校验到的条件 | 展示状态 / 下一动作 |
|---|---|
| 计划有效但当前 G2 缺失 | WAITING_FOR_G2，按原职责形成决定 |
| G2 已拒绝 | G2_REJECTED，处理原拒绝依据 |
| 已冻结但工作包缺交接 | IMPLEMENTATION_INCOMPLETE，完成对应工作包 |
| Writer 明确受阻 | IMPLEMENTATION_BLOCKED，显示原阻塞项 |
| Writer 完成但候选缺失或已有较新交接 | CANDIDATE_REQUIRED，采集核验并由原运行时登记候选 |
| LEAN 候选已核验 | LEAN_SELF_VALIDATION_REVIEW，复核冻结 Writer 控制；不因没有独立 QA/Reviewer 而阻塞 |
| STANDARD / CONTROLLED 缺 QA 或 Reviewer | 分别列出 QA_RESULT_REQUIRED 或 REVIEW_RESULT_REQUIRED |
| 本轮无就绪阻断项可运行，或 QA 已受阻 | TEST_PREREQUISITE_WAIT，等待新的解除证据 |
| QA FAIL 或 Reviewer CHANGE 已记录 | QUALITY_CHANGES_RECORDED，沿原路由核验修复映射 |
| 同候选完整 QA 观察与 Reviewer APPROVE 齐全 | QUALITY_OBSERVATIONS_COMPLETE，由原运行时继续核验汇合并保存其事实 |

上表是查询结果，不是新的路由枚举。QualityPassed 始终为 false，HumanAccepted 在可支持状态为 false、无法判定时为 null。它不会把观察齐全当作最终质量放行，也不会把单独 Writer COMPLETED、QA PASS 或 Reviewer APPROVE 写成人工业务已验收。

首轮明确支持 GATE_DECISION、WRITER_HANDOFF、CANDIDATE_STATE、TEST_READINESS、QA_RESULT、REVIEW_RESULT 的上述查询子集。ROUTING_DECISION、HUMAN_ACCEPTANCE、HUMAN_RECOVERY、FACT_CORRECTION、其他未知事件或 SupersedesEventRef 需要现有运行时解析，本候选遇到时返回 UNDETERMINED，而不是擅自解释其含义。因此后置汇合、人工验收、工程合并和归档状态不由本工具声明完成。

QA/Reviewer 的已有结构、同候选引用、轮次、时间、非零失败和复用约束继续交给原校验器。额外核对当前计划中的完整 QA 验证集合、ControlId 和 GateClass，拒绝空集合 PASS 或缺项。局部查询不冒充完整运行时验证；NextActions 是对原流程的提示，实际执行前仍须重新核验动态前提与当前候选。

## 候选与规则来源衔接

当前只支持[候选快照](候选快照.md)工具的 SnapshotFormatVersion=v1.0。正式候选事实需由现有运行时登记 CandidateRef，并绑定 CandidateSnapshotRef、CandidateSnapshotDigest、BaseCommitSHA、WriterHandoffRefs；DraftOnly 草稿或 LocalOnly 快照不被当作正式候选。

查询实际调用 B2 的 verify_snapshot，核对快照摘要、真实 Git 基线、交接原始字节、交付内容与当前工作树，以及上下文包、Profile、Plan 的治理输入摘要。文件在候选后改变、同版计划原地改写、交接覆盖遗漏或快照篡改都不能显示为已核验候选。旧格式/缺少治理输入绑定的候选保留为无法判定，不自动迁移或重新登记。

若需求目录保存了可选 rules-projection.json，查询会调用[规则组合](规则组合.md)的来源核验接口，检查其 Sources 原字节是否仍匹配，展示 RuleSourcePinsVerified。该结果不证明投影正文、适用模块选择或人工授权，RuleRequirementAuthorizationVerified 保持 false；投影是否已进入当前正式上下文包继续按原规则处理。

## 修复交接导航

Observations.RepairLinks 展示已有 Reviewer FindingId、原评审事件、受影响工作包及后续显式关联的 Writer Changes。链接使用既有 Changes.EvidenceRefs 中的“评审事件引用#FindingId”，不创建第二套修复台账，不通过自然语言相似度猜测问题已修复。

没有明确链接时保持 NO_EXPLICIT_REPAIR_LINK；有对应修改时仍为 RUNTIME_VERIFICATION_REQUIRED。Writer 事实引用与 SelfValidation 条目数量提供验证证据导航，不能替代新候选的测试或独立 Reviewer 判断。跨候选的旧 PASS 不会由本查询复用或改绑。

## 一致性与边界

- 读取前后核对当前需求根计划/Markdown 和全部事实 JSON 的原始字节摘要；变化时返回无法判定，不把半读状态展示为确定结果。
- 输出 Sources 可用于定位本次观察的输入，但不是签名或新事实源；查询不修改这些文件。
- 缺文件、解析异常、敏感内容、路径越界/符号路径、Git 重定向污染、重复事件和来源冲突只输出通用错误码，不回显配置或解析正文。
- 当前最多读取 1024 份相关输入，每份不超过 1 MiB。没有数据库、联网、常驻监听或新的状态缓存。
- 退出码 0 表示已校验到本工具支持的状态，1 表示无法判定，2 表示调用参数或需求编号错误；0 不代表质量或人工验收通过。

专用验证使用临时 Git 仓库与合成事实，覆盖 Writer 完成但无候选、真实 B2 核验、LEAN 无空 QA、缺独立结果、QA 有效集合遗漏、陈旧 Markdown、未知/纠错和查询全树只读。公司项目真实试用及非本机平台仍待后续验证。
