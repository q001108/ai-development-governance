# 固定发行的项目接入与升级

状态：2026-10-28，C4/C5 未发布开发候选。已在独立 Codex CLI/app-server 实例验证原生安装、技能发现和自然语言触发 B1；桌面 UI 操作及公司项目真实试用待验证。工具不执行 Git 提交、发布或业务需求迁移。

## 社区构建

在社区仓根构建新的发行目录；输出必须在社区仓外且尚不存在。已提交源码默认要求干净；本轮未提交候选需显式允许，发行会记录 SourceDirty=true。

```powershell
python scripts/governance_package.py build --repo . --output ../outputs/governance-candidate --allow-dirty
python scripts/governance_package.py verify --package ../outputs/governance-candidate
```

release.json 保存源码提交、候选标记、插件/治理/测试版本及每个文件的原始字节 SHA-256。PackageDigest 是该对象按 UTF-8、键排序、紧凑 JSON、无末尾换行序列化后的 SHA-256。它证明制品内容一致，来源可信仍依赖受信任的分发和仓库审阅。发行中只携带通用资源，不携带社区 Git 数据、测试夹具、真实需求或项目凭据。

插件版本当前为 `0.1.0-dev.5`，治理保持 `v3.0.2`、测试保持 `v3.0.1`；需求管理增量格式另绑定 v1.0。插件封装不等于治理版本升级。

## 初始化与升级

用指定发行中的管理器生成预览；项目必须是实际 Git 仓根。以下占位路径按实际项目替换，预览文件应在目标项目之外且尚不存在。

```powershell
python <发行目录>/scripts/governance_project.py preview --repo <目标项目> --package <发行目录> --output <项目外预览.json>
python <发行目录>/scripts/governance_project.py apply --repo <目标项目> --plan <项目外预览.json>
```

预览列出文件动作、旧基线/项目现状/新模板摘要、冲突及 Git 状态摘要，不复制项目文件正文。apply 重新计算预览并逐项比对；预览过期、被修改或存在冲突时拒绝执行。项目接入与升级依各次任务授权执行；本轮只在合成项目验证，未修改公司仓。

安装后主要结构：

```text
.governance/project.json                 项目维护的适配引用
.governance/plugin.lock.json             默认发行、保留发行及托管文件基线
.governance/run.py                       校验后执行锁定发行
.governance/entry.md                     AGENTS 链接的短入口
.governance/local/                       被忽略的本地报告、会话和临时资源
.governance/releases/<PackageDigest>/    原样保留的完整发行
docs/、rulepacks/、.codex/agents/          当前默认发行的兼容镜像
scripts/governance_*.py                  指向同一运行器的小入口
docs/requirements/<ID>/plugin-binding.json  每个新需求的固定依赖
```

AGENTS 保留原文，仅添加带标记的入口块；不整文件替换。project.json、项目规则/测试声明、业务记录及需求导航由项目维护。核心文档、Schema、规则包及角色保留托管基线；直接修改发行目录会使校验失败。镜像便于原路径调用与阅读，需求实际使用的通用资源以其绑定发行为准。发行管理器从指定新包运行，不在项目 scripts 中生成管理器或打包器的无效转发入口。

接入还会在保留原 .gitattributes 内容的前提下添加受限托管块，仅对固定发行、托管文件和适配入口设置 -text，防止 Git 自动换行破坏原始字节摘要。实际生效属性在应用时核对；子目录或开发者本机属性覆盖此约定时拒绝并回滚。已验证 core.autocrlf=true 下提交后重新克隆仍能校验和运行；自定义过滤器、组织策略及其他平台仍需项目侧核对。

新接入的 project.json 同时声明 LocalRuntimeDirectory=.governance/local，保留原 .gitignore 后添加该目录的精确忽略块，供工作区沙箱内运行。它不依赖写入受保护的 .git。已有项目的 project.json 继续由项目维护，不随插件升级覆写；采用新运行目录需要项目显式更新该字段。目录继承项目权限，不作为凭据库；已跟踪内容不得被接管为本地缓存。

升级采用三方比较：项目未改可更新；上游未改则保留项目定制；双方改动则报告冲突；已有同字节文件可明确识别为接管。未受托管的不同内容不覆盖，要写入的已有未提交文件不覆盖。上游移除的托管文件暂保留，旧发行全部保留，不自动递归清理。写入使用临时文件替换和进程互斥，锁定记录最后更新；失败时尝试撤销本次仍保持原写入内容的文件，不覆盖并发的新修改。进程或系统崩溃后的恢复仍需检查，非跨文件系统事务。

已有公司副本式接入可在 preview 中显式选择 --preserve-existing。该模式保留已有通用副本、项目角色与脚本，不把它们冒充上游托管文件；只为缺失兼容文件及新运行器建立所有权。CompatibilityMode=PRESERVE_EXISTING 固定在项目配置，后续升级继续保留。既有 scripts 仍是原实现，新能力使用 .governance/run.py。固定发行资源仍读选定包，项目特有的附加治理/版本文档及其本地链接继续从项目读取；Schema 及包拥有的规范不能借此从另一发行借用。该模式不撤销项目已有的直接开发例外，项目适配器需显式保持其适用范围。

本版只允许治理/测试规范版本相同的插件升级。跨治理版本迁移、旧副本项目的冲突合并及既有未绑定需求迁移需要单独工作，不通过更新默认版本推断批准。

## 需求绑定与实际调用

主智能体在新需求取得唯一 ID 后、创建基线和其他治理产物前自动绑定。此操作固定工具依赖，不代表 G1/G2 或任一质量门禁通过。已有绑定不覆盖；已有工件但无绑定的目录拒绝自动接管。

```powershell
python .governance/run.py bind --requirement-id REQ-DEV-20261028-01
python .governance/run.py governance_tools check --repo .
python .governance/run.py governance_status --repo . --requirement-id REQ-DEV-20261028-01
```

运行器从需求 ID 或标准需求工件路径选择原发行。多个需求、输入位于其他项目、缺少必要绑定或制品损坏时拒绝运行。查询不创建绑定；工具帮助及没有需求上下文的项目级查询可使用默认发行。项目路径始终相对项目根，发行资源相对包根。

工具本身没有需求参数时，增加由运行器消费的选择器：

```powershell
python .governance/run.py governance_rules --for-requirement REQ-DEV-20261028-01 --repo . --project governance.rules.json
python .governance/run.py governance_test_session test --for-requirement REQ-DEV-20261028-01 --repo . --session-id <SessionId> --validation-id V-02
python .governance/run.py governance_test_session stop --for-requirement REQ-DEV-20261028-01 --repo . --session-id <SessionId>
```

选择器必须与工具实际输入的需求一致。新发行只能成为新需求的默认依赖，旧需求继续执行保留目录中的工具，并读取其 Schema、治理/测试规范和规则包；业务工件、领域规范及历史 Git 来源仍来自项目。人工/智能体阅读规范时也必须按 plugin-binding.json 定位原发行，不能只阅读当前默认镜像。候选快照额外绑定 plugin-binding.json 的原始字节，后改绑定会使原快照失效。

这些命令是接入和诊断接口。项目采用技能入口、候选能力及本地 Automatic 配置后，由主智能体在既有阶段调用，开发者无需按每条需求维护环境清单或逐次输入命令。原生隔离测试已观察到自动读取技能、原需求绑定和规范、调用 B1 并完成测试及清理；具体证据见[原生加载验证](原生加载验证.md)。真实公司开发闭环仍待试用。
