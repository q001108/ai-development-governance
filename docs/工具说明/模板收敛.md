# 项目通用模板收敛

通用模板正文在每个完整固定发行中保留，项目通过需求绑定读取；项目目录维护专用规则和真实需求记录。收敛不改变模板正文、门禁语义、历史记录或既有绑定，也不要求每次需求复制全部模板。

## 按需求读取

```powershell
python .governance/run.py template --kind baseline --requirement-id <ID>
python .governance/run.py template --kind context --requirement-id <ID>
python .governance/run.py template --kind development --requirement-id <ID>
python .governance/run.py template --kind qa --requirement-id <ID>
python .governance/run.py template --kind review --requirement-id <ID>
```

输出 ResourceRef、LogicalRef、内容摘要及实际插件版本。AI 完整读取 ResourceRef 指向的正文再形成相应产物，不能把导航页当作模板或自行拼接当前默认发行路径。template 是项目路由器的只读命令，即使需求已退出治理仍可查询；它不创建绑定、需求、事实或批准。未绑定的历史需求明确拒绝，不采用当前默认版。

登记前仅预览默认模板时显式使用 `template --kind baseline --default`，不能把预览当作已登记需求的版本选择。项目升级后已有需求仍定位其保留发行。`.governance/templates.md` 提供默认预览链接及同一命令说明；其链接不替代每需求绑定。

## 收敛布局

项目在 `.governance/project.json` 显式声明 `TemplateLayout=RELEASE_ONLY` 后，后续接入/升级不再生成五份通用模板的 docs 镜像。省略该字段或使用 MIRRORS 时保持原行为，不静默改变旧项目。

启用布局不会自动删除或覆盖旧副本。先比较项目模板和发行正文，识别公司定制及原批准来源，再核对 AGENTS、角色、脚本、规范和历史记录引用。真正的项目规则继续在项目中保留，不能因收敛而丢失。

存在历史引用时，旧路径可保留项目维护的简短兼容导航页，列出读取命令、默认预览和原始 Git 版本入口；导航页明确不是 FROZEN 模板正文。必要的旧锚点只作导航，不复制对应规则。原模板已在可定位的 Git 提交中保存且逐字核对后，才移除重复正文；不得仅凭同名文件认为语义相同，也不得覆盖未提交定制。

新产物使用已绑定发行，历史未绑定记录继续按其正式版本及原 Git 来源解释；页面中的历史入口不代表已自动解析每份需求当年的完整语义。不得改写历史实例来追随新模板，不能删除保留发行内部的模板来节省空间。升级器保留不再镜像的已有路径，不会自动递归清理。

## 项目角色和检查

项目 AGENTS 和实际使用的规划/归档角色应明确上述模板选择方式，保留原角色职责、模型、写入边界及人工门禁。原规范中的模板文件名可以继续作为逻辑资源名，程序通过固定发行选择真实正文。

验证应覆盖：旧需求选择旧发行；默认预览必须显式；未知/未绑定需求拒绝；发行内容篡改拒绝；镜像移除后新需求仍能生成基线；后续升级不恢复重复正文；现有机械检查、历史链接与必要锚点可用。模板收敛本身不授权迁移业务需求或自动 Git 提交。
