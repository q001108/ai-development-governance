# 开发上下文包模板

模板状态：`FROZEN`
模板版本：v3.0
生效日期：2026-09-16

> 适用阶段：G1 后的 DRAFT 技术规划到 G2；LEAN 由主智能体精简规划，STANDARD / CONTROLLED 使用总控编排器 `Invocation: EXECUTION_PLANNING`。
> 输入：已通过 G1 人工需求确认的需求基线。
> 目标：作为 G1 通过后的唯一需求级技术执行控制契约，冻结后续实现、验证与只读评审必须遵守的边界。

## 填写规则

- 只引用已由 G1 确认的需求基线，不复制原始需求、当前问题、业务影响、业务结果或证据正文。
- 最终范围、归属边界、契约、验收标准、风险、验证、工作包、执行模式和 G2 决策必须由已批准需求、项目规范及当前仓库事实支持，不得推测补齐。
- “任务点”与“工作包”是同一概念，统一使用 `WorkPackageId`；第 2 节是工作包定义和依赖关系的唯一来源。
- `ApplicableRules` 是开发规范的按需投影，具体边界见第 1.5 节，不得将全部规则转换为检查清单。
- 契约只描述必须保持或实现的行为，不描述代码写法，也不自动创建 API、字段、事件、权限、交互或迁移方案。
- 本模板只记录技术执行计划和 G2 决策，不记录实际操作、验证 / 评审结果、运行时路由、人工业务总验收或工程交付事实；实际过程投影到 `开发记录.md`。
- 新产物固定使用 `开发上下文包.md`。目录、`RequirementId`、历史别名和冲突处理遵循[治理运行时事实协议](./治理运行时事实协议.md)。

| `ValidationId` | `Source` | `GateClass` / `GateTarget` / `Trigger` | `Owner` / `AffectedWorkPackages` | 环境依赖 / `Readiness` / 派发前检查 | `EvidenceReuse` | `EstimatedCost` |

执行控制字段：

- `Source` 必须引用 AcceptancePlan 中对应 RB/QG/AD 的 `ControlId`，可同时引用 `PROFILE:<GovernanceProfile>`、`RISK:<id>`、`RULE:<RuleId>`、`USER:<稳定引用>`；不得直接从技术来源生成 BA，不得使用“最佳实践”或“更严格”作为阻断来源。
- `GateClass` 使用 `BLOCKING` 或 `ADVISORY`；`GateTarget` 使用 `CANDIDATE_QUALITY` 或 `NON_QA_FOLLOW_UP`。LEAN 中触发的 RB/QG 为 `Owner=WRITER / BLOCKING / CANDIDATE_QUALITY`，由 Writer 保存结果；STANDARD / CONTROLLED 中 `Owner=QA` 的触发阻断项进入 QA 有效集合并参与既有汇合。AD 始终为 `ADVISORY / NON_QA_FOLLOW_UP`，不得阻断。
- `Trigger` 必须是可客观求值的条件，并在 G2 记录 `TRUE` / `FALSE` 及依据。`FALSE` 表示不进入有效验证集合，不得记为 `NotExecuted`；可能影响阻断项且仍为未知时保持 `DRAFT`。
- `Owner` 与类别必须一致：BA=`HUMAN_ACCEPTANCE`；RB=`WRITER / QA / REVIEWER`；QG=`WRITER / QA`；AD 可使用明确责任方但永不阻断。第一阶段不允许 CI/RELEASE_PIPELINE Owner。LEAN 的触发 RB/QG 只允许 Writer；STANDARD 第一阶段必须同时规划独立 QA 与 Reviewer；CONTROLLED 还必须满足人工 G2。
- 环境依赖必须使用明确类型和稳定入口，例如 `BROWSER_SESSION`、`BACKEND`、`DATABASE`、`EXTERNAL_SERVICE`、`CREDENTIAL`、`OS` 或 `NONE`。规划时 `Readiness` 使用 `READY`、`PLANNED` 或 `N/A`；`PLANNED` 必须同时给出准备责任方、客观完成条件和派发前 `ReadinessCheck`，未知状态不得冻结。
- `EvidenceReuse` 使用 `RERUN_REQUIRED`、`SAME_CANDIDATE` 或 `REFERENCE_ONLY`。复用条件必须预先定义，不得由 QA 或总控临时解释；普通 Writer 自测只能为 `REFERENCE_ONLY`，不能直接替代独立 QA。`SAME_CANDIDATE` 只允许在 `CandidateRef` 和候选摘要均未变化时复用同一候选既有 `PASS`；跨候选复用一律禁止，不得通过差异边界、相同文件或总控判断设置例外。
- `EstimatedCost` 使用 `S（≤2 分钟）`、`M（>2～10 分钟）`、`L（>10～30 分钟）` 或 `XL（>30 分钟或依赖人工 / 外部环境）`。`L` / `XL` 必须说明无法用更小验证覆盖同一风险的依据。

具有写入副作用的构建只有在已核实不会修改任何 Git 跟踪源码或候选内容，且所有输出路径已在本上下文包中预声明为可丢弃验证产物时，才可设置 `Owner=QA`。此类验证必须在运行时分配的隔离工作树中执行；隔离工作树及预声明产物由运行时在验证结束后整体回收，QA 不得自行删除、恢复或覆盖用户文件。不能同时满足这些条件的构建不得进入 QA 有效验证集合，应调整验证方法或保持上下文包 `DRAFT`。

> 验证只定义需要验证什么，不填写执行结果。命令必须以当前仓库实际脚本和配置为准，且不得具有修改业务源码的副作用。第 5.4 节定义全局默认证据策略；验证定义表仍须逐项写明“继承第 5.4 节”或具体例外。
