# Codex 运行时拓扑

状态：`FROZEN`
版本：v3.0
生效日期：2026-09-16

## 目的

本文定义角色组织、调用关系和读取入口。阶段与路由条件以[主流程](./多智能体协同开发治理流程.md)为准，机器事实以[事实协议](./治理运行时事实协议.md)为准。现有 `Codex运行时拓扑-v1.5.svg` 仅作历史参考，不表示当前流程。

Profile 判级、控制分类和角色最小集以[治理配置与验收控制规范](./治理配置与验收控制规范.md)为准。

## 运行时拓扑

“运行时”是治理责任抽象，不表示 Codex 自带项目编号、候选快照、计数、持久化或恢复；调用主智能体或项目工具必须显式承担这些责任。

成功路径：需求基线 → G1 事实及摘要绑定 → 技术只读审计 → DRAFT ControlProfile、AcceptancePlan 与上下文包协同收敛 → 重新判级及 live G2 资格校验 → G2 事实及冻结 → 初始化 Profile 对应记录 → Writer → 候选控制 → 人工 BA → 人工授权最终提交与归档。LEAN 由 Writer 完成触发 RB/QG；STANDARD / CONTROLLED 按计划触发独立 Reviewer/QA 与既有汇合。

## Profile 角色拓扑

| Profile | 必需逻辑角色 | 条件角色 | 禁止做法 |
|---|---|---|---|
| `LEAN` | 主智能体/运行时、单一 Writer、人工 BA | N/A；出现独立判断需求先升级 | 为形式并行、创建空 QA/Reviewer、让 AD 阻断 |
| `STANDARD` | 运行时、总控规划、Writer、独立 QA、独立 Reviewer、人工 BA | N/A（第一阶段沿用双结果路由） | 用 Writer 自测替代独立角色 |
| `CONTROLLED` | 运行时、总控、Writer、独立 QA、独立 Reviewer、人工 G2、人工 BA | 专业审批责任方 | 角色自批、取消硬触发器或用成本降级 |

逻辑角色不等于必须创建同数量的 Codex 子智能体；是否调用子智能体必须服从 Profile 和职责独立性。

## 按角色与阶段读取

所有角色读取根 AGENTS、自己的角色配置及调用方提供的当前有效输入。下表列出的协议章节含下级小节；领域规范按 `ApplicableRules` 读取。调用方必须提供精确来源，引用无法定位则报告缺项，不得用转述摘要代替权威规则。

| 角色 / 阶段 | 必需治理来源（除当前输入外） |
|---|---|
| 总控 REQUIREMENT_AUDIT | 需求基线模板；主流程“G1、G2 与 UCR 边界”；协议“需求目录与标识”“文件名与历史兼容”“敏感信息与证据” |
| 总控 EXECUTION_PLANNING | 开发上下文包模板；主流程“G1、G2 与 UCR 边界”“执行模式”；项目开发总则；协议“测试就绪与增量复验”“敏感信息与证据”“证据位置与保留” |
| 总控 EXCEPTION_ROUTING | 主流程“候选质量汇合与路由”“核心规则”；协议“质量汇合与路由事实”“连续计数”“敏感信息与证据” |
| Writer | 协议“写入交接与任务执行事实”“敏感信息与证据”“证据位置与保留”；冻结上下文包及工作包直接相关规则 |
| QA | 协议“角色结果时间”“不可变候选”“测试就绪与增量复验”“敏感信息与证据”“证据位置与保留”；冻结验证与就绪 / 复验事实 |
| Reviewer | 协议“角色结果时间”“不可变候选”“Reviewer 结果不变量”“敏感信息与证据”；候选、交接及冻结静态审查边界 |
| 归档 | 归档规范、开发记录模板；协议“文件名与历史兼容”“持久化顺序与恢复”“需求迭代版本与全局台账”“敏感信息与证据”“证据位置与保留”；阶段2再读全局台账 |

主智能体承担运行时职责时仍须读取完整事实协议与主流程。上表不缩小规则效力；只有事实、版本和引用未变化时，才可复用已读取内容；候选摘要、环境就绪和权限等可变事实仍须重新核验。出现未覆盖的真实异常时按需读取其权威章节，不因此全量重读所有规范。

## 总控编排器

唯一总控只按显式 `Invocation` 工作，不推断或合并调用：

- `REQUIREMENT_AUDIT`：形成轻量基线、准备 G1，不做技术审计。
- `EXECUTION_PLANNING`：有效 G1 后形成范围、契约、工作包、归属、验证及执行模式；G2 按主流程决定。
- `EXCEPTION_ROUTING`：仅分类运行时无法机械处理的异常，不重判正常结果。
- `INTEGRATION_ROUTING`：仅供明确绑定 v2.0 及更早版本的历史需求，旧规则无法定位时停止。

完整调用输入与原始输出契约见[总控配置](../../.codex/agents/orchestrator.toml)。总控不分配运行时标识、计数或主要业务实现。

## 写入槽位

统一 Writer 按当前冻结上下文包动态绑定工作包、槽位、归属和工作区；不固化领域子角色。任务点统一使用 `WorkPackageId`，不得另建编号。模式为 `SINGLE / DEPENDENCY-SEQUENTIAL / BOUNDED-PARALLEL`，依赖驱动，最多同时2个写入槽位，不强行并行。

Writer 输出实际操作和代码单元级修改事实，不创建候选、不派发角色、不改规划。完整输入与交接契约见[Writer配置](../../.codex/agents/writer.toml)。

## 候选状态与运行时记录责任

运行时分配标识、核验与保存门禁、交接、候选及角色结果，承担[持久化顺序与恢复](./治理运行时事实协议.md#持久化顺序与恢复)。事件是机器事实源，Markdown 仅为异步投影；角色不能通过修改记录改变事实。

质量结果先校验再保存，正常路由机械生成、异常返回总控。不得以投影失败触发角色重跑，也不得将缺失原始事实从 Markdown 补造。

## 临时质量验证

STANDARD / CONTROLLED 中实际触发的 QA 独立且不写业务源码，只执行冻结且已触发的归属验证，不修复候选、不写阶段记录。LEAN 的机械 QG 由 Writer 执行，不冒充独立 QA。运行时负责逐项就绪与复验计划、工作树分配及回收。QA 仅返回验证事实，不拥有路由或人工验收权限。完整输入和原始输出契约见[QA配置](../../.codex/agents/qa.toml)。

## 只读评审者

Reviewer 在 STANDARD / CONTROLLED 被控制计划触发时严格只读，候选保存后可与 QA 并行；只审查静态候选、契约、范围、风险和测试源码充分性，不要求、读取或重判 QA 动态结果，也不执行测试、修复或改写记录。LEAN 不默认触发 Reviewer；一旦需要独立静态判断，先升级 STANDARD。`APPROVE / CHANGE` 只表示静态审查结论。完整契约见[Reviewer配置](../../.codex/agents/reviewer.toml)。

## 本地、交付平台与 Codex 桌面适配

- Windows、macOS 与 Linux 均可作为本地开发和快速 QG 环境；命令必须使用实际平台语法，单平台结果不得外推为跨平台通过。
- 交付平台和验证能力由接入项目在 ControlProfile 中如实声明。当前项目不存在的 CI、发布流水线或平台验证必须标记为不可用，不能被模板虚构为已通过。
- Codex 桌面仅提供会话和多智能体执行能力，不自动提供 RequirementId、候选快照、Profile 判级、JSON 校验、持久化或恢复。
- 主智能体承担运行时责任。LEAN 使用单 Writer；STANDARD / CONTROLLED 只在依赖允许时并行，最多 2 个不重叠写入槽位。`.playwright-cli/` 等会话产物默认不进入 Git。

## 路由

正常条件、优先级、等待、回派、双失败合并、三次终止和迟到结果处理，唯一采用[主流程路由表](./多智能体协同开发治理流程.md#候选质量汇合与路由)。运行时结果持久化与处置控制遵循[质量汇合与路由事实](./治理运行时事实协议.md#质量汇合与路由事实)；只有异常才调用总控，不新增路由或重判质量结论。

## 原则

实现、QA、Reviewer保持独立职责，权限不得从别的角色继承。人工业务总验收不能被代码完成、QA或评审通过替代。归档角色不属于开发主拓扑，仅在人工验收后按[归档规范](./开发溯源归档规范.md)完成两阶段核验和交付登记。
