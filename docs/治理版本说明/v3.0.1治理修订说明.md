# v3.0.1 治理修订说明

版本：v3.0.1；状态：`COMMUNITY-BASELINE`。

## 适用边界

本社区版以 v3.0 为基础并合并 v3.0.1 增量。接入项目必须在自身 `AGENTS.md` 中明确启用范围；只有显式绑定 v3.0.1 的新需求使用新增规则。历史需求不重新编号、不改写原始事件、不回填新字段。

修订重点是测试归因、受控验证调整、环境等待与同轮恢复、开发者 ID、格式兼容和版本绑定，不改变三档 Profile 判级、人工业务验收及人工 Git 交付边界。

## 版本与基线绑定

v3.0.1 的 ControlProfile、AcceptancePlan 使用匹配的 SchemaVersion、GovernanceVersion；ControlProfile 的 DecisionRulesVersion 同为 v3.0.1。v3.0 的既有文件继续按 v3.0 校验。事件 envelope 仍为 v1.1，机器 FactProtocolVersion 仍为 v2.1；不要把文档版本直接写进事件机器协议字段。

新 ControlProfile 增加唯一事实源 `BaselineBindings`：

| 字段 | 内容与校验 |
|---|---|
| Governance | Version=v3.0.1；SourceRef 指向本修订说明；SourceDigest 为规范化文本 SHA-256；Revision 为可选固定 Git revision |
| BusinessRevision | 本次业务代码起点的完整 commit SHA；必须能解析到真实 commit，与治理版本分别记录 |
| Testing | Version=v3.0.1；SourceRef 指向测试规范；SourceDigest 与可选 Revision 固定实际使用内容 |

两份文档的版本、摘要和来源均单独核验。Revision=null 表示用当前文件内容摘要绑定，允许未提交的候选验证；不代表接入项目已经启用该版本。开发上下文包只引用该字段，不再抄写三组版本值。业务候选的未提交文件及内容摘要继续由候选事件记录，不能以 BusinessRevision 代替最终候选摘要。

## 冻结验证计划的受控纠正

原 AcceptancePlan 的历史保留规则不变。不在原文件里删除、改写或降级阻断项。需要替代验证时，在当前需求的 `adjustments/ADJ-NNN.json` 保存一份不可变调整记录，由以下命令校验并计算有效验证集合：

```powershell
python scripts/governance_tools.py validate-adjustment --adjustment <调整记录路径>
```

普通需求不创建该文件。此机制仅处理 `PREEXISTING_FAILURE`、`BASELINE_UNATTRIBUTABLE`、`VALIDATION_DEFINITION_INVALID`，且必须保留原始 BLOCKED 与证据。存在候选可归因 FAIL 时回到返工，不能用调整机制清除失败。原本属于环境不可用的问题优先等待恢复，不用调整绕开必要环境验证。

此类冻结门禁调整需要独立判断，适用于 STANDARD/CONTROLLED；LEAN 出现无法由原计划解决且需要独立判断的情形时，先沿既有升级规则处理，不给普通 LEAN 增加常驻 Reviewer。

### 调整记录的机器字段

新版 QA 的 ObservedFailures 每项增加 `Attribution=CANDIDATE / PREEXISTING / UNATTRIBUTED`、非空 ValidationIds 与 EvidenceRefs。只有 CANDIDATE 推导候选 FAIL；其他实际测试失败仍保留，必要验证无法完成时保持 BLOCKED。缺失归因不默认当作既有失败。进入调整的归因证据也须纳入 EvidenceDigests，并绑定 OriginQADigest，禁止批准后换掉来源。旧 v3.0 事件不回填该字段，按原始事实只读分析。

| 字段 | 含义 |
|---|---|
| GovernanceVersion / RequirementId | v3.0.1 和当前需求；路径绑定该需求 adjustments 目录 |
| OriginalPlanRef / OriginalPlanDigest | 原始冻结 AcceptancePlan 的路径与摘要 |
| ControlProfileRef / ControlProfileDigest | 已校验 Profile 的路径与摘要 |
| CandidateRef / CandidateEventDigest | 当前候选事件路径及摘要 |
| G2Ref / G2Digest | 当前上下文包已冻结的门禁事件及摘要 |
| OriginQARef / OriginQADigest | 同候选、上下文与谱系的原始 ACTIVE/BLOCKED QA 事件及摘要 |
| Reason / EvidenceRefs / EvidenceDigests | 受控纠正原因、归因证据引用及每份证据的摘要；EvidenceDigests 也必须包含全部 CoverageEvidenceRefs |
| Replacements | 待替代控制的方法、原验证 ID、成本及风险覆盖证据 |
| ReviewerRef / ReviewerDigest | 独立 APPROVE 事实及摘要；绑定当前候选和具体调整内容 |
| ApprovalRef / ApprovalDigest | 人工批准的 HUMAN_RECOVERY 事实及摘要；不由程序自动生成批准 |

每个 Replacements 条目包含 `ControlId`、`OriginalValidationIds`、`Statement`、`Method`、`MethodKind`、`EstimatedMinutes`、`CoverageEvidenceRefs`。原 QA 的有效验证或未执行条目必须明确包含 `ControlId`，禁止把另一个无关阻塞借来替代当前控制。CoverageEvidenceRefs 需列入 EvidenceDigests。

只允许调整原已触发阻断 RB/QG 的技术验证表述、方法及估算成本。ControlId、Class、Owner、平台、Blocking、Triggered、RiskTargetId 与 BA 全部保持；原 Statement 仍保存在原计划中。有效 Statement 应准确描述替代集合，例如“相关 Agent/Binding 回归通过”，不能仍声称“全服务端测试通过”。独立 Reviewer 控制不可替换。替代集合须覆盖同一原子风险及必要回归面；机械校验只能证明字段和引用一致，风险等价性必须由独立 Reviewer 在覆盖分析中说明，并由人工批准。

Reviewer 的 REVIEW_RESULT 使用正式 Decision=APPROVE，候选摘要核验为真，无 Findings/EvidenceIssues；人工 HUMAN_RECOVERY 使用 Decision=APPROVED 和可定位 ApprovalRef。二者 Payload 均包含 AdjustmentDigest。其计算使用整个调整对象去除 ApprovalDigest、ReviewerDigest 后，以键排序紧凑 JSON 序列化，再按脚本 content_digest 计算。这样可以先计算提案摘要，后记录评审和批准，避免自引用摘要循环。批准后修改方法、原计划、候选或证据，会导致校验失败。

### 执行与汇合

运行时先校验原 Profile/Plan，再校验调整记录。校验返回的 EffectiveControls 是当前候选的验证输入；ValidationPlanRef 保留原计划引用，同时将 AdjustmentRef/AdjustmentDigest 传给 QA 和 Reviewer。QA 只执行有效集合并如实返回新的结果；调整校验结果固定 `QualityPassed=false`，不能作为 QA PASS 或人工 BA。

调整后新 QA 轮次仍绑定同一原始候选；若需要修改测试源码或产品代码，则形成新候选，旧调整不能直接复用，须重新收集该候选的阻塞事实、覆盖分析与批准。跨候选证据复用仍禁止。执行中只能采用一个明确指定的有效调整记录；不同调整记录不能由运行时自行叠加，更新调整应从原计划完整列出本次所有替代，并取得针对新内容的评审和批准。

QA 结果必须记录 AdjustmentRef/AdjustmentDigest；汇合前重新校验该记录与候选，检查有效集合完整通过，再与同候选静态评审汇合。原全量套件失败和原 BLOCKED 保留，最终只能表述“替代验证集合通过”，不能宣称原全量测试通过。权限、安全、ZIP、事务或迁移的真实风险不能被“既有失败”理由省略。

运行时在汇合前执行只读命令：

```powershell
python scripts/governance_tools.py validate-adjusted-quality --adjustment <调整记录路径> --qa-result <QA事件路径> --review-result <Reviewer事件路径>
```

它检查批准后的实际结果时间、同候选与调整摘要、QA 控制完整覆盖、执行方法、阻断结果、独立静态 APPROVE，以及是否已有更新候选或 ACTIVE 结果。返回 ReadyForHumanAcceptance=true 仅表示可进入人工业务验收，HumanAccepted 始终为 false。复用只允许同调整下已实际执行的 PASS，必须指向直接来源并带复验计划；不能复用批准前的旧验证。

若当前 STANDARD/CONTROLLED 计划另有 Writer 归属的阻断控制，或事件包含待运行时解析的 FACT_CORRECTION，本命令停止并报告，不凭 QA/Reviewer 两份输入宣称所有责任已闭合。运行时必须核验这些额外事实并处理原始异常；不得删除原控制或历史纠正事件来通过工具。
